Install

  • Download the signed and notarized DMG from Releases, drag Dblore to Applications.
  • Needs macOS 14+ on Apple Silicon.
  • Updates itself: Dblore > Check for Updates…
  • Opens .sqlite, .sqlite3 and .db files from Finder, and .duckdb files once the DuckDB plugin is installed.

Connect

  • PostgreSQL: host, port, user, database. SSL modes from disable to verify-full, timeouts, retry on failure, read-only mode.
  • MySQL and MariaDB: host, port, user and database (required; the sidebar shows only that database). Direct or through an SSH tunnel. Users with caching_sha2_password or mysql_native_password; sha256_password and MariaDB ed25519 are not supported.
  • MySQL SSL: only Verify CA and Verify Full check the server certificate. Allow, Prefer and Require encrypt the connection without checking it, so on an untrusted network an active attacker could read the traffic and the password. Allow and Prefer also fall back to plain text when the server offers no SSL. A client certificate needs Require, Verify CA or Verify Full.
  • MySQL full password: when the server asks for the full password (caching_sha2_password with no cached login) and the connection does not verify the server's certificate, Dblore stops instead of sending it and says to choose Verify CA or Verify Full. A direct connection to 127.0.0.1, ::1 or localhost is exempt.
  • SSH tunnel (PostgreSQL, MySQL, MariaDB and MongoDB; MongoDB takes a single host, no mongodb+srv://): password or ed25519/ECDSA private key (RSA is not supported). A key passphrase is never stored. The first connection asks you to trust the host key; a changed host key blocks the connection.
  • Client certificate: authenticate with a certificate, keep its passphrase in the Keychain and pick a custom certificate authority. A custom CA also works on its own, without a certificate.
  • Statement, lock and idle-in-transaction timeouts: global in Settings > Results, overridable per connection.
  • Passwords are stored in the Keychain.
  • MongoDB: a mongodb:// or mongodb+srv:// string, or the form. See MongoDB.
  • SQLite: pick a file in the connect modal. Features the engine cannot support are hidden.
  • DuckDB: needs the plugin.
  • Import Connections… (welcome screen or File menu) reads .pgpass, a PostgreSQL, mysql:// or mariadb:// URI, DBeaver (with saved passwords), TablePlus and DataGrip, and a Dblore connections file. Preview and pick before importing; duplicates are flagged.
  • Export connections: the welcome screen's Connections tab exports chosen connections, and optionally an open workspace's favorites, to a Dblore file. Passwords, SSH secrets, keys, certificates and file databases are never exported. On import, connections already saved are skipped, a connection string pointing at other hosts is dropped, SSH tunnels and weaker settings are flagged, and favorites go into one folder without duplicates.
  • Scripts: a connection can run your own scripts and get its password from a command. See Connection scripts.
  • The welcome screen lists saved and recent connections (up to 50). Hover a card to remove it.
  • The footer shows the connection name, the Safe Mode cues and a No SSL badge when the connection is not encrypted. A MySQL connection encrypted without a checked certificate shows Unverified SSL.

Connection scripts

  • The Scripts section of the connection form picks up to three scripts: Before connecting runs first, and a failure stops the connect; Password command prints the password on its first output line, used for that connect only and never saved (engines that use a password); After disconnecting runs once the connection is closed, or when the connect fails after the first script. Quitting Dblore runs the after-disconnect scripts.
  • Scripts live in ~/Library/Application Scripts/ace.thi.Dblore, the only folder macOS lets Dblore run your scripts from. Open Scripts Folder opens it in Finder, creating it when missing. A script is a plain file name in that folder: anything that resolves outside it is refused.
  • Arguments: the connection's host, port, user and database, in that order. Quote them in your script and pass -- before them to other commands. A host, user or database that starts with - or holds a control character is refused, and the script does not run.
  • Script timeout: 1 to 300 seconds, 30 by default. A script that times out keeps running: macOS gives Dblore no way to stop it.
  • Scripts run with your own environment, outside the app sandbox. Their output is never logged or stored, since a password command prints a secret. Only a before-connect failure shows the start of its error output, in the message to you; logs see the script name and exit status only.
  • Imported connections never bring scripts with them: choose them in the connection form.

Workspaces & tabs

  • A workspace (.sqlws) holds your tabs: notebooks, .sql files, Markdown notes and table data viewers.
  • Several tabs and windows. Drag to reorder, middle-click to close.
  • Drag a tab outside the window to open it in a new window (same as Open in New Window; pinned and unsaved tabs stay).
  • Switch with Cmd+1 to Cmd+9. Reopen a closed tab with Cmd+Shift+T.
  • Optional native macOS window tabs: enable Settings > General > Open new windows as tabs. Cmd+Shift+N or the + button opens a new window tab, Ctrl+Tab switches, Cmd+T opens a new tab. The header stays in the title bar, and the window tab bar sits below it, starting after the left sidebar; each window tab keeps its own Dblore tabs.
  • Drag a window tab out of the tab bar (or use Window > Move Tab to New Window) to split it into its own window.
  • Tabs and window state are restored on relaunch. Settings > General chooses between the welcome screen and the last session at startup.
  • Command palette: Cmd+K finds and runs commands.

Notebooks

  • Notebooks are .dblore files made of SQL cells, with inline results under each cell.
  • Run the cell with Ctrl+Enter, run and move on with Shift+Enter, run and insert below with Option+Enter, run all with Cmd+Shift+Enter.
  • Cancel a running query. Each result shows row count and execution time.
  • New cell Cmd+Option+N, duplicate Cmd+D, delete Cmd+Delete. The floating toolbar of a cell has a Format SQL button.
  • Named parameters: write :name in a cell and fill the values in the inline form under it. You choose whether the values are saved in the file.
  • Old .sqlnb files: rename them to .dblore, the content is unchanged.

SQL editor

  • Open a .sql file in a tab (Cmd+Shift+J for a new one).
  • For quick notes, Cmd+Shift+M opens a Markdown note in the workspace. It is written to a .md file only when you press Cmd+S; the eye button in the header switches between the source and an editable preview.
  • Run the query with Cmd+R or Cmd+Enter.
  • Named parameters (:name) are bound from the right sidebar.
  • Table- and column-aware autocomplete: Up / Down to choose, Enter or Tab to accept.
  • Toggle comment with Cmd+/. Format SQL, word wrap and syntax highlight toggles sit in the editor toolbar.
  • Explain with Cmd+E, Explain Analyze with Cmd+Shift+E (runs the statement, so it asks first).
  • Snippets: type a trigger word and accept it from autocomplete. See SQL snippets.

SQL snippets

  • Write snippets in Settings > Editor > Snippets: Add snippet, then a name, a trigger and a body, with a preview. Up to 200 snippets.
  • Trigger: 1 to 32 letters, digits, underscores or hyphens, unique. Type it in a SQL editor; autocomplete offers the snippet, and accepting it inserts the body in place of the trigger.
  • In the body, ${1:default} is tab stop 1 with its default text, ${1} an empty tab stop, $0 where the caret ends (the end of the text when there is none) and \$ a literal dollar sign. A bare $1 stays as written, so PostgreSQL parameters are safe.
  • Tab moves to the next tab stop and Shift+Tab to the previous one, in number order. Reaching the final caret, or moving the caret out of the current stop (a click, an arrow key), ends the snippet.
  • Snippets are local data: Settings > Data exports and clears them with the rest.

Sidebar

  • Left sidebar (Cmd+B) has three tabs: Schema, Favorites and History.
  • Schema: tables, columns, types and triggers, grouped by schema. Click a table to browse its data in a preview tab. Right-click a table for Edit Structure… (see Structure editor).
  • View Source on a function, procedure or trigger opens its definition read-only, with Copy and Open as editable copy.
  • Type in the filter field of a tab for a loose fuzzy match.
  • Favorites: save SQL snippets in folders, double-click to insert.
  • History: every query is recorded locally. Filter by status, or show only writes. Search also matches the source or kind badge, such as "AI Assistant".
  • The schema visualizer is a canvas of tables with foreign-key lines you can toggle. It can copy or save the tables shown as Mermaid or Graphviz DOT.
  • PostgreSQL: Sequences and Types sections (enums, domains and composite types), loaded when opened, with Show DDL and Copy Name.
  • Folders: group tables and views into folders per connection with Move to Folder or a drag; rename or delete a folder from its menu. The eye menu hides schemas you do not use from the sidebar; SQL, autocomplete and search still see them.
  • Find a value in every table: the button next to the schema filter (or the command palette) searches the text of every column in up to 500 tables, one at a time on a separate read-only connection, with Contains or Equals, 50 rows and 10 seconds per table, and Cancel. Click a match to open the table filtered to it. PostgreSQL, MySQL/MariaDB and SQLite.
  • Query Insights: the History tab's chart button groups the queries you ran by shape (values replaced by ?, IN lists folded) over 24 hours, 7 or 30 days, per connection: runs, average, p95 and slowest time, error rate and last run, sortable, with Open in Editor.
  • Right sidebar (Cmd+Shift+B) shows cell details, column filters and highlights.

Results grid

  • Sort, resize (double-click a divider to auto-fit), search and paginate.
  • Edit values inline. Changes are staged and committed as one batch, or applied directly depending on Safe Mode. Undo staged changes from the Edit menu.
  • Foreign keys: look up the referenced row while editing, or jump to it.
  • Pin result, re-run, then Compare: added, removed and changed rows are highlighted. Two EXPLAIN plans compare node by node. A notebook cell's pin is saved with its results.
  • Column header filter, plus a filter sidebar that builds WHERE conditions. Filters can be saved.
  • Highlight matching cells or rows from the sidebar.
  • Open a cell in the detail panel, with a JSON viewer and string beautifier.
  • Show Row Details (the details button in a row's # cell, or the right-click menu of a cell or of #) opens the whole row in the right sidebar, one field per column. In an editable result, change values there: edits stay drafts, marked with a dot, until Apply; Cancel drops them. Key, generated and read-only columns are not editable.
  • Add Row in the grid menu opens a form in the right sidebar: one field per column, a NULL button, checked against the column type. An empty field is left out of the INSERT, and Add stages the row.
  • Settings > Results > Color Values by Type shows numbers, text, dates, booleans and JSON in their own soft colors.
  • View Query shows the exact SQL sent, including the row limit.
  • Several cells at once: select rows, then right-click a column. Set Value… writes the same text, NULL or DEFAULT (PostgreSQL and MySQL) into every selected cell; Generate UUID / Generate UUIDv7 writes a different UUID into each one (uuid, text and long enough character columns). One staged change, one Undo.
  • Copy: Copy as Markdown in the grid menu, and Settings > Results > Copy rows as chooses what Cmd+C copies: TSV (the default), TSV or CSV with headers, CSV, JSON or Markdown. A copied text value that starts like a formula gets an apostrophe in front, as in CSV exports; Neutralize Copied Formulas in Settings > Results turns it off.
  • Invisible characters (control, zero-width, special spaces and direction controls) show as visible marks, with their code points in the tooltip. Copy, export and search use the real text. Show Invisible Characters in Settings > Results turns it off.
  • Cell Value draws PostGIS geometry and geography and MySQL GEOMETRY values, with the shape type, point count, SRID and Copy WKT. pgvector vector, halfvec and sparsevec values show their dimension, norm, minimum, maximum and first values. A value over 256 KiB opens as plain text at once.
  • Updates and deletes need a primary key: a change to a table without one is refused and names the table.

MongoDB

  • Connect with a connection string or the form. Logins use SCRAM-SHA-256 or SCRAM-SHA-1 (a user created in admin needs Auth Source admin). TLS is off or Verify Full, with an optional custom CA.
  • Commands: cells and SQL files take a subset of the mongosh syntax (find, aggregate, countDocuments, distinct, insertOne/insertMany, updateOne/updateMany, replaceOne, deleteOne/deleteMany, show collections). Dblore parses it itself and never runs JavaScript.
  • Browse: click a collection in the sidebar. The filter bar takes a filter document such as {status: "active"} and runs it on the server.
  • Grid or Documents: the picker under a result switches between the grid and document cards. A card shows the top-level fields; click a nested object or array to expand it.
  • Edit in place: double-click a value on a card (or a grid cell) to edit it, Return to send, Esc to cancel. Each edit runs one $set on that field after the Safe Mode confirmation. A double-click on an object, array or other type opens the field editor. The card header opens Row Details in the right sidebar, and a field's right-click menu has Show Details.
  • Add, duplicate, delete: in the data viewer, stage them by _id, preview the exact insertOne/updateOne/deleteOne commands, then Commit. Results whose _id mixes types are read-only.
  • Build Aggregation… in the collection menu builds a pipeline stage by stage, with a read-only preview of each stage.
  • Collection sections: next to the collection title, Documents, Aggregations, Schema and Indexes switch the view. Schema analyzes the sampled documents; Indexes lists each index with its type, size, usage and status.
  • Filter bar tools: the options button sets projection, sort, collation, hint, skip, limit and maxTimeMS; the bookmark button saves queries; Explain shows the plan as a tree; Export Code writes the query as Node.js, Python, Java, Go or C# driver code.
  • Aggregations: run a pipeline from the Aggregations section, built stage by stage or typed as text, with Wizard templates, saved pipelines, Explain and Export. Click a stage for the common operators, double-click to type any operator.
  • AI button: the filter bar and the Aggregations section write a filter or pipeline from a prompt (Stop, then Apply).
  • Administration: the Indexes section creates, hides and drops indexes, a Validation section edits the collection's validator, and the sidebar creates, renames and drops collections and views. The same commands (createIndex, createCollection, collMod and others) work in a .js tab. Drops ask for the typed name first.
  • Bulk Update / Delete… in the Documents header changes every document that matches the filter, after a count preview; an empty filter or 1,000 or more documents needs the collection name typed.
  • Databases: the Databases button in the sidebar lists the server's databases; create, drop or switch to one (the workspace reconnects).
  • JSON view: the picker under a result also offers JSON. The view mode and page size are remembered per collection.
  • Export and import: Export... writes a collection, a query or an aggregation as Extended JSON or CSV; Import Documents... reads a JSON, NDJSON or CSV file after a preview.
  • Back Up Database / Restore Backup (File menu) save collections and views, with indexes and validators, to one .ndjson file and read it back.
  • An aggregation that ends in $out or $merge runs from the Aggregations section after the Safe Mode confirmation.
  • Query files: a new query in a MongoDB workspace is a .js file; .sql files are refused there.
  • MongoDB has no transactions, so writes ask before they run instead of waiting for Commit. For agents over MCP, use a user with a read-only role.

Structure editor

  • Right-click a table in the sidebar and choose Edit Structure….
  • PostgreSQL and MySQL: add, rename and drop columns; change type, default and nullable; create and drop indexes; add and drop primary, foreign, unique and check constraints.
  • SQLite: only the changes SQLite supports directly: add a column, rename a column (SQLite 3.25+), drop a column (3.35+), create and drop indexes. Constraints cannot be changed, and a key, indexed or generated column cannot be dropped; the table is never rebuilt.
  • DuckDB: View Structure… is read-only.
  • Changes are staged first. The preview shows exactly the SQL that runs, and Safe Mode confirms it like other schema changes. Each Apply is recorded in History.
  • On PostgreSQL and SQLite the changes run together and join the pending transaction in Protected mode. On MySQL each statement commits on its own, so the editor is disabled in Protected (Review) mode, with pending changes or with your own transaction open; if a statement fails, it reports how many were applied.
  • Closing the editor drops staged changes that were not applied.

Compare Schemas

  • File > Compare Schemas… compares two schemas of the same engine: PostgreSQL, MySQL/MariaDB or SQLite. The target is a schema of this tab's connection, the only place a script ever runs. The source is another schema of this connection, or a saved connection of the same engine, read on a short-lived connection that is closed after the read.
  • Compared: tables only in the source (create) or only in the target (drop), and in tables of both, columns added, dropped or changed (type, nullability, default), indexes and foreign keys added, dropped or changed. Views, routines, types, primary keys, unique and check constraints, comments, identity and generated columns are not compared. A renamed table, column or index shows as a drop plus an add.
  • Tick the items to include. The script pane shows the exact SQL that Run sends, with Copy Script and Save Script….
  • Drops of tables, columns, indexes and foreign keys are unticked by default; ticked drops ask first (Run with Drops), since their data cannot be recovered. Lossy type changes are flagged, and changes that cannot be scripted are listed to make by hand instead of run.
  • Run goes through Safe Mode like the structure editor: on PostgreSQL and SQLite the script runs as one and joins the pending transaction in Protected mode; on MySQL each statement commits on its own, stopping at the first failure, with a report of what ran. A connection that changed since the compare is refused before anything is sent. Compare again after a run.

Charts

  • Switch any result between grid and chart with the toggle beside the result actions.
  • Chart types: bar, line, area, point.
  • Split by draws one small chart per value of a column (up to 12), with shared axes and one legend. The PNG export includes the whole grid.

Export

  • Formats: Excel, CSV, TSV, JSON, Markdown, PDF and SQL INSERT.
  • Copy results as SQL INSERT or an IN list.
  • Per-format options with reset, redaction, wrapping and a size check.
  • File > Export SQL Dump… writes a PostgreSQL, MySQL/MariaDB or SQLite database to a .sql file (all tables or a few, with or without data). File > Restore SQL Dump… checks every statement of a Dblore dump before running it. File > Copy Database File… saves an open SQLite database as one file. A dump holds your data in clear text.
  • File > Export Data Dictionary… writes the columns, indexes and foreign keys of every table as a Markdown or a standalone HTML file (no scripts, no remote content).

Import data

  • Import Data… from the File menu or a table's context menu: CSV, TSV, JSON and newline-delimited JSON.
  • Preview rows and NULL values, map columns, override inferred types, review the SQL, then import into an existing or a new table. A running import can be cancelled.

Safe Mode

  • Five protection levels.
  • Confirmation before DROP, TRUNCATE, ALTER and CREATE. Warning on DELETE or UPDATE without WHERE.
  • Pending transactions show a Commit / Rollback banner; View Details shows every pending statement in full. Touch ID, or your Safe Mode password, unlocks changes.
  • Commit style (footer or Settings > Security): Immediate, Confirm, Review or Password, for dialogs, unlocks and inline edits.
  • Read-only connections block writes.
  • Related rows before a delete: when staged changes delete rows, Preview SQL and the Safe Mode dialog list what else the delete touches: rows deleted by cascade, rows set to NULL or to their default, and rows that still refer to the deleted ones. A foreign key that would block the delete disables Commit and names the constraint; Commit Anyway lets the database decide. The counts run on a separate read-only connection within 5 seconds, and are skipped while a transaction is open.
  • Large reads inside transactions are capped with a server-side cursor (PostgreSQL).
  • MySQL commits implicitly before DDL, TRUNCATE, LOCK TABLES, grants and similar statements, so Protected mode refuses them. Turn Protected mode off for the connection to run them.

AI assistant

  • Toggle the chat panel with Cmd+L. It writes SQL from plain-language questions and explains or fixes queries.
  • Bubble mode: the detach button in the panel header turns it into a floating circle at the bottom of the window. Click the circle to expand or collapse the chat, drag it left or right to move it, hover it and click the small x to hide it, and press Esc to collapse it. Choose the default in Settings > AI > Panel (Right sidebar or Bubble).
  • Providers: Anthropic, OpenAI, Google Gemini, OpenRouter, xAI, Requesty (its router forwards requests to the model vendor), ChatGPT sign-in, Ollama, LM Studio, mlx_lm.server, any custom OpenAI-compatible endpoint, or on-device MLX models (Qwen3.5 2B, 4B and 9B, Gemma 4 12B). Settings > AI > Unused model files removes files of models that are no longer offered.
  • On-device models need the On-device AI plugin: without it, Settings > AI shows Install…. Models download separately from Hugging Face; every file is checked by its size and SHA-256 before the model is installed, and models are kept when you remove the plugin.
  • Bring your own API key. Claude Pro/Max subscriptions are not supported.
  • Sent automatically: table and column names, types and keys.
  • Sent only after you review and press Send: query text and error messages.
  • Row data is never sent on its own. Generated SQL does not run automatically.
  • Run read-only queries (Settings > AI > Privacy, off by default): the assistant writes a query, Dblore runs it and shows you the rows. Only a single read-only statement runs, in a read-only transaction; anything else is refused and shown as SQL. Row values and errors are never sent to the model.
  • In bubble mode, drag an edge of the card to resize it.
  • The chat can also call tools of MCP servers you add, one approved call at a time. See Outside MCP servers.
  • For fully local use, point it at Ollama, LM Studio or mlx_lm.server.

MCP server

  • Lets AI agents such as Claude Code and Cursor read your databases through the Model Context Protocol. Off by default: turn on Run the MCP server in Settings > MCP. Dblore must be running.
  • The server listens on this Mac only, at http://127.0.0.1:<port>/mcp (default port 41730). Use only the port Settings shows as running.
  • Every request needs the Bearer token from Settings > MCP. Copy Claude Code command copies a claude mcp add command to paste in a terminal; Copy Cursor JSON copies the entry for Cursor's mcp.json. Regenerate creates a new token; clients with the old one stop working until you copy the setup again.
  • Agents see only the connections you turn on in the list. DuckDB connections cannot be shared.
  • Tools: list_connections, list_tables, describe_table and run_query, plus execute_write when write tools are allowed (see MCP write tools).
  • run_query is read-only: one statement per query, checked first and then run in a read-only transaction (SQLite files open read-only). Writes, DDL, SET, CALL and several statements are refused. A query returns 200 rows by default (at most 1000), cells are cut at 2000 characters and a query stops after 30 seconds.
  • Use a least-privilege database user: an agent can read everything the connection's role can read, including other databases on the same server.
  • Query results go to the agent. Treat them as untrusted data: text stored in a table can try to give the agent instructions.
  • Agent queries are recorded in History (when History is on). They do not see uncommitted changes in Dblore's own open transaction.

MCP write tools

  • Off by default: turn on Allow write tools in Settings > MCP. Agents can then ask to run one change at a time through the execute_write tool.
  • Once write tools are on, each connection turned on in the list gets an Agent access scope: Read (the default, no changes), Read + data changes (INSERT, UPDATE, DELETE and MERGE; MongoDB inserts, updates and deletes) or Read + data + schema changes.
  • Schema changes cover tables, indexes, views, sequences, schemas, types, domains and MySQL databases, TRUNCATE, RENAME TABLE and COMMENT ON; on MongoDB, createCollection, createIndex, dropIndex, drop and renameCollection in the same database.
  • Refused before anything is asked: creating, changing or dropping functions, procedures or triggers (use the SQL editor); on MongoDB, collMod, hiding or unhiding an index, createView, dropDatabase, system collections and pipelines that name another database; statements with hidden characters, privilege or account changes, extensions, foreign data or file access; more than one statement.
  • Changes run with the connection's protection and commit style. A connection whose commit style is Review or Password refuses agent changes: set Confirm or Immediate to allow them.
  • Every call opens the MCP Write Request panel, even when only the welcome window is open. It shows the connection and engine, the kind of change, the exact statement and the client name (as the client reports it, unverified). Approve once runs it once; Deny or Deny all refuse. Return never approves, and Approve is ignored for a moment after a request shows, so a click meant for something else never approves it.
  • There are no standing grants: every call asks again. Requests show one at a time, at most three wait (a further one is refused at once), and a request not answered 2 minutes after it shows is denied. Turning off write tools or MCP, or taking a connection's scope away, denies the waiting requests.
  • Approve only statements you have read: an agent can be steered by text stored in the database.

Outside MCP servers

  • Settings > MCP > Outside MCP servers adds an MCP server whose tools the AI chat may call: a name, a URL and an optional token.
  • The URL must be https, or plain http to 127.0.0.1, ::1 or localhost. Redirects are never followed.
  • The token is sent as a Bearer token and kept in the Keychain. It is listed and deleted with the other secrets in Settings > Data.
  • A new server starts turned off, with no tools allowed. Test connects to it and lists its tools; tick the ones the AI chat may use, then turn the server on.
  • If the server later changes a tool's description or schema, the tool shows Changed and is unticked until you review it and tick it again. Text from the server is shown with hidden and direction characters removed.
  • In the AI chat: on a connection whose AI access allows it, the chat can offer the allowed tools of enabled servers, never with an on-device model. Each call shows a card with the server, the tool and the exact arguments. Nothing is sent until you press Run once, which accepts clicks only after the card has been shown for a moment; every call asks again. Deny tells the assistant the call was denied.
  • Results are untrusted: the tool's result goes back to the assistant marked as data from a third party, never as instructions, and nothing in it can run SQL. Arguments the card cannot show exactly (hidden characters, or longer than the card) are refused. A server that does not answer within 10 seconds is left out of that turn, with a note in the chat.
  • Add only servers you trust: a server can return text that tries to steer the AI.

Plugins

  • Optional engines and features, installed from Settings > Plugins. Dblore downloads a signed, notarized library or bundle and checks its SHA-256 and signature before it loads it. Remove deletes it; a plugin in use stays loaded until you quit Dblore.
  • DuckDB: open a .duckdb file (read-only by default), create one or use an in-memory database. Query Parquet/CSV File… in the command palette queries a file directly.
  • Safe Mode guards DuckDB writes such as INSTALL, ATTACH, COPY … TO and CREATE TABLE. Row edits, data import and foreign-key lookup are not available.
  • On-device AI: runs AI models on this Mac with MLX for the AI chat and inline suggestions. See AI assistant for models.

Settings & data

  • Open with Cmd+,. View keyboard shortcuts in Settings > Shortcuts.
  • Search sections from the sidebar of the settings modal.
  • Light or dark theme (also the toggle in the header) and an accent color. Settings > Appearance > Animations turns interface animations on or off; System follows macOS Reduce Motion.
  • Settings > General > Confirm before quitting with Cmd+Q asks first. Quitting from the Dock or the menu bar never asks.
  • Long-query notifications (Settings > General, off by default): a macOS notification when a query runs longer than a threshold. It never shows the SQL or data; clicking it opens the tab.
  • Editor font size, word wrap, side-by-side layout and a configurable result row cap.
  • Safe Mode levels. AI keys are stored in the Keychain.
  • Updates: toggle background checks.
  • Data tab: export, import or clear local data as a .dblorebackup package, with progress, a Cancel button and a toast when it ends. Secrets are never included. Saved SSH passwords, keys and trusted host keys can be deleted here.
